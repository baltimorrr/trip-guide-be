# Phase 1: Schema mappings and fixtures

## Overview

Migration V8 creates `hotel_policies` and `reviews`. The phase maps every column the detail page reads but no entity
maps yet, extends the local demo seed so the page has data, and adds the test fixtures the later phases use. It adds
no endpoint. It's done when the app starts (Flyway V8 + `ddl-auto: validate`) and the existing suite passes
unchanged.

## Context

- `spring-base/CLAUDE.md`: table naming and convention decisions (2026-10-21); "Persistence"; "Conventions"
  (never edit a run migration, standard columns from V2); "Tests" (fixtures, `smallint` reads back as `Integer`).
- `DATABASE-SCHEMA.md`: `hotel_policies`, `reviews`, `review_status`, and the `Ref:` lines for `reviews`.
- `db/migration/V3__…` (`hotels`, `addresses`, `hotel_photos`, `room_types`), `V5__…` (policy rules), `V6__…`
  (`hotel_amenities.is_free`, `room_type_beds.quantity`, `room_type_amenities`). Follow V6's header comment style.
- Mapping precedents:
  - `Hotel.checkInFrom` (`@JdbcType(LocalTimeJdbcType.class)` for wall-clock times)
  - `Destination.normalizedName` (a `text` column as a plain `String`)
  - `User.roles` (`@ElementCollection`)
  - `WishlistEntry` (the class doc says why it differs)
- `test/.../support/CatalogFixtures.java`: `HotelBuilder`, `photo`, `roomPhoto`, `hotelAmenity`, `bed`,
  `cancellationRule`.

## Requirements

- Functional: the tables and columns below exist and are mapped read-only. The demo seed shows a full detail page
  for every demo hotel. There are **no demo reviews** (user decision).
- Non-functional:
  - Search SQL and behaviour are untouched.
  - The new mappings are lazy and never loaded by the search or wishlist paths.
  - Seed statements are idempotent (the repeatable migration re-runs whenever its checksum changes).

## Architecture

### V8 `V8__create_hotel_policy_and_review_tables.sql`

```sql
-- Hotel policies (C-HOTEL-03) and customer reviews (C-HOTEL-07), read by the hotel detail page. Table and column
-- names follow DATABASE-SCHEMA.md; ids, version and audit timestamps follow this project (see V2). Enum-like columns
-- hold the Java enum names.

-- What a guest should know before arriving, one paragraph per row. Check-in/out times and the minimum check-in age
-- are columns of hotels.
create table hotel_policies (
    id          bigint generated by default as identity primary key,
    hotel_id    bigint      not null references hotels (id) on delete cascade,
    policy_type varchar(20) not null
        check (policy_type in ('CHILDREN', 'EXTRA_BED', 'PETS', 'SMOKING', 'DEPOSIT', 'PAYMENT', 'OTHER')),
    description text        not null,
    sort_order  smallint    not null default 0,
    version     bigint      not null default 0,
    created_at  timestamptz not null,
    updated_at  timestamptz not null
);

create index hotel_policies_hotel_id_idx on hotel_policies (hotel_id);

-- One review per stay. booking_id gets its foreign key to bookings in the migration that creates that table; until
-- then nothing writes reviews (C-MYBK-05). No cascades: the schema keeps reviews when a hotel or user row goes.
create table reviews (
    id               bigint generated by default as identity primary key,
    booking_id       bigint      not null,
    hotel_id         bigint      not null references hotels (id),
    user_id          bigint      not null references users (id),
    score            smallint    not null check (score between 1 and 10),
    title            varchar(200),
    body             text,
    traveller_type   varchar(20) check (traveller_type in ('SOLO', 'COUPLE', 'FAMILY', 'BUSINESS', 'GROUP')),
    status           varchar(20) not null default 'PUBLISHED' check (status in ('PUBLISHED', 'HIDDEN')),
    owner_reply      text,
    owner_replied_at timestamptz,
    version          bigint      not null default 0,
    created_at       timestamptz not null,
    updated_at       timestamptz not null,
    constraint uk_reviews_booking_id unique (booking_id)
);

-- The hotel page lists published reviews, newest first.
create index reviews_hotel_id_created_at_idx on reviews (hotel_id, created_at desc) where status = 'PUBLISHED';
```

   `min_check_in_age = 21` for the hostel.

   rows yet.
6. One tiered platform policy, "Free until 72 hours before check-in" (refundable): rules `(72, PERCENT, 50)` and

## Implementation Steps

1. Back up `spring-base/` without `target/` to the scratchpad (`rollback/spring-base-before-c-hotel-detail.tgz`) and
   confirm `git status` is clean.
2. Write V8 as above.
3. Add the enums, embeddables and entities, then the new fields on the existing entities, and update their docs.
4. `./mvnw test -Dtest=ProjectApplicationTest`. The context starts only when Flyway applies V8 and Hibernate
   validates every new mapping. If validation rejects a mapping, fix the mapping, never the migration.
5. Extend `CatalogFixtures`.
6. Extend the demo seed. Run the app locally twice in a row (port 8081 per `.env`). The second start must re-run
   nothing harmful: there must be no duplicate photos or policies. Spot-check with `psql` (port 5434):
   - `select count(*) from hotel_policies` doesn't change between starts
   - every demo address has coordinates
   - Mỹ Khê's room-only plans use the tiered policy
7. `./mvnw verify`: all existing tests pass with the same count as before this phase.

- [x] V8 applies on a fresh database. Hibernate validation passes with every new mapping.

## Risk Assessment

- **Element collections on `Hotel`/`RoomType` vs `ddl-auto: validate`.** `hotel_amenities` and `room_type_beds` have
  composite PKs that Hibernate doesn't model for an element collection. Validation checks only that the columns exist
  and that their types match, so this is expected to pass. If a mapping is rejected, fall back to a small entity with
  `@IdClass` (the `WishlistEntry` pattern) for that link table.
- **Lazy collections leaking into search.** They are never touched outside the detail queries. JPQL joins in phases
  2–3 read them without loading them. Don't add `fetch = EAGER`.
- **Seed churn.** Changing the repeatable seed makes Flyway re-run all of it on the next local start. Each new
  statement guards itself (`where not exists` / `is distinct from`). Step 6 checks this.
- **Switching Mỹ Khê to the tiered policy moves its `freeUntil` on search cards (24 h → 72 h) in local demo data
  only.** Tests build their own hotels and are unaffected.
- Rollback: restore the backup, or delete the new files and revert the edited ones (`git checkout -- <paths>`). Undo
  V8 locally with `docker compose down -v`, or drop both tables and V8's `flyway_schema_history` row.
