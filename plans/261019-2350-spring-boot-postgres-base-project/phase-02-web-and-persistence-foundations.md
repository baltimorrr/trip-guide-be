# Phase 2: Web and persistence foundations

## Overview

Add the shared building blocks every feature reuses: a JPA base entity (id, version, timestamps), consistent RFC 9457 ProblemDetail error responses, domain exceptions, and OpenAPI/Swagger UI. It adds no business features yet.

Context: [phase 1](./phase-01-scaffold-project-and-infrastructure.md), [research report](./reports/researcher-261019-2350-spring-boot-4-ecosystem-versions-report.md)

## Key Insights

- Use Hibernate `@CreationTimestamp`/`@UpdateTimestamp` instead of Spring Data auditing. They need no `@EnableJpaAuditing` and work in `@DataJpaTest` slices with no extra imports. `@CreatedBy` is not needed, so Spring Data auditing would add nothing.
- Extending `ResponseEntityExceptionHandler` gives ProblemDetail bodies for all built-in Spring MVC exceptions (400s, 404 `NoResourceFoundException`, 405, 415…). Do NOT also set `spring.mvc.problemdetails.enabled`, which would register a duplicate advice.
- The catch-all `Exception` handler is a trap. Phase 3 MUST add explicit `AccessDeniedException`/`AuthenticationException` handlers, or `@PreAuthorize` denials become 500s.
- springdoc is not managed by the Boot BOM, so pin `3.1.1` (the Boot 4.1 line).

## Requirements

- Functional: every error response is `application/problem+json` with `status`, `title`, `detail`, `instance`; validation errors add `errors: [{field, message}]`
- Functional: Swagger UI at `/swagger-ui.html`, spec at `/v3/api-docs`; both disabled under the `prod` profile
- Non-functional: 500 responses never leak exception messages, SQL, or stack traces; the server logs the full error

## Architecture

```text
common/
├── persistence/BaseEntity.java      @MappedSuperclass: id, version, createdAt, updatedAt
├── error/GlobalExceptionHandler.java @RestControllerAdvice extends ResponseEntityExceptionHandler
├── error/ResourceNotFoundException.java   → 404
├── error/BadRequestException.java         → 400
├── error/ConflictException.java           → 409
└── config/OpenApiConfig.java        API info (bearer scheme added in phase 3)
```

Exception → status map:

| Exception | Status | Detail shown to client |
|-----------|--------|------------------------|
| `MethodArgumentNotValidException` (override) | 400 | "Validation failed" + `errors[]` (field + message only, never the rejected value) |
| `jakarta.validation.ConstraintViolationException` | 400 | `errors[]` from violations |
| `PropertyReferenceException` (bad `?sort=`) | 400 | "Unknown sort property: x" |
| `BadRequestException` | 400 | message from code (e.g. "Password must be at most 72 bytes") |
| `ResourceNotFoundException` | 404 | "Product 42 not found" |
| `ConflictException` | 409 | message from code (e.g. "Email already registered") |
| `DataIntegrityViolationException` | 409 | generic "Request conflicts with existing data" |
| `ObjectOptimisticLockingFailureException` | 409 | "Resource was modified concurrently, retry" |
| `Exception` (fallback) | 500 | "Unexpected error"; logged at ERROR with stack |

## Implementation Steps

1. `BaseEntity` (Lombok getters only; subclasses decide setters):
   ```java
   @MappedSuperclass @Getter
   public abstract class BaseEntity {
       @Id @GeneratedValue(strategy = GenerationType.IDENTITY) private Long id;
       @Version private Long version;
       @CreationTimestamp @Column(nullable = false, updatable = false) private Instant createdAt;
       @UpdateTimestamp @Column(nullable = false) private Instant updatedAt;

       // Identity equality: entities are equal only when both are persisted with the same id.
       @Override public boolean equals(Object o) {
           if (this == o) return true;
           if (o == null || Hibernate.getClass(this) != Hibernate.getClass(o)) return false;
           return id != null && id.equals(((BaseEntity) o).id);
       }
       @Override public int hashCode() { return Hibernate.getClass(this).hashCode(); }
   }
   ```
   Every table therefore has the columns `id bigint generated by default as identity`, `version bigint not null`, `created_at timestamptz not null`, `updated_at timestamptz not null`. Migrations in phases 3 and 4 must match.
2. Exceptions: `ResourceNotFoundException(String resource, Object id)` → message "%s %s not found"; `ConflictException(String message)`; `BadRequestException(String message)`. All extend `RuntimeException`.
3. `GlobalExceptionHandler`: implement the table above. Use a private helper `problem(HttpStatus, String detail)`. Override `handleMethodArgumentNotValid` to add an `errors` property. Log 5xx at ERROR, 4xx at DEBUG.
4. `OpenApiConfig`: `@OpenAPIDefinition(info = @Info(title = "spring-base API", version = "v1"))`.
5. `application-prod.yml`:
   ```yaml
   springdoc:
     api-docs.enabled: false
     swagger-ui.enabled: false
   ```
6. Test `ErrorResponseTests` (`@IntegrationTest`):
   - `GET /does-not-exist` → 404, content type `application/problem+json`, body has `status: 404`
   - `GET /v3/api-docs` → 200 JSON with `openapi` field
   - Specific handlers (400/404/409) are tested through the real endpoints in phases 3 and 4. No test-only controller is needed, which would otherwise break once security arrives.

## Risk Assessment

| Risk | Mitigation |
|------|------------|
| springdoc 3.1.1 incompatible with Boot 4.1.1 at runtime | the `/v3/api-docs` test catches it; fall back to the newest 3.1.x on Maven Central |
| Catch-all handler swallowing security exceptions | explicit handlers in phase 3 + a 403 test in phase 4 |
| `Hibernate.getClass` import confusion | `org.hibernate.Hibernate` |

## Security Considerations

- No stack traces or SQL in responses (`server.error.include-stacktrace` stays at the default `never`)
- Validation errors echo only field names + constraint messages, never submitted values (avoids reflecting passwords)
