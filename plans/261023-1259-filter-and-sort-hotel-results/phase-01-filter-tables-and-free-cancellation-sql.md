# Phase 1: Filter tables and free-cancellation SQL

## Overview

Migration V6 adds what the new filters read but the database lacks: amenities (facilities and room features), bed
types, their links to hotels and room types, and `free_cancellation_until()`, the SQL twin of the Java free-cancellation
rule. It also adds entities for the two master tables, fixtures for tests and demo data for local runs. No API change
yet.

## Context

- `spring-base/DATABASE-SCHEMA.md`: `amenities`, `hotel_amenities`, `room_type_amenities`, `bed_types`, `room_type_beds`
- `spring-base/CLAUDE.md`: table conventions (identity bigint ids, `version`, audit timestamps; enum-like columns as
  varchar + CHECK holding UPPERCASE Java enum names; composite-key tables without id/version, like `user_roles`)
- `V3__create_hotel_catalog_tables.sql` (`accommodation_types` insert pattern), `V5__create_rate_and_tax_tables.sql`
  (`board_types` insert pattern, `night_price()` style)
- `search/model/FreeCancellation.java` + `FreeCancellationTest` (the rule being twinned)

## Requirements

- Functional: the tables and master rows exist; `free_cancellation_until(policy, checkIn, checkInFrom, zone)` gives the
  same instant as `FreeCancellation.until` (before the "after now" check) for every case it covers; fixtures can attach
  amenities, beds, stars, accommodation type, distance and currency to test hotels; the demo seed has them too.
- Non-functional: Hibernate `validate` passes; existing tests untouched and green.

## Architecture

```sql
-- V6__create_amenity_and_bed_tables.sql
create table amenities (
    id bigint generated by default as identity primary key,
    code varchar(50) not null, name varchar(100) not null, group_name varchar(60) not null,
    scope varchar(10) not null check (scope in ('HOTEL', 'ROOM')), icon varchar(50),
    version / created_at / updated_at (standard),
    constraint uk_amenities_code unique (code));
insert into amenities ... -- master rows, see below

create table hotel_amenities (           -- composite key, no id/version (like user_roles)
    hotel_id bigint not null references hotels (id) on delete cascade,
    amenity_id bigint not null references amenities (id),
    is_free boolean not null default true,
    primary key (hotel_id, amenity_id));
create index hotel_amenities_amenity_id_idx on hotel_amenities (amenity_id);

create table room_type_amenities (room_type_id → room_types on delete cascade, amenity_id → amenities, pk both);

create table bed_types (id, code varchar(20) unique, name varchar(60), standard columns);
insert into bed_types ... ('single','Single bed'), ('double','Double bed'), ('queen','Queen bed'),
                          ('king','King bed'), ('twin','Twin beds');

create table room_type_beds (room_type_id → room_types on delete cascade, bed_type_id → bed_types,
    quantity smallint not null default 1 check (quantity >= 1), primary key (room_type_id, bed_type_id));

-- SQL twin of FreeCancellation.until (change both): the moment free cancellation ends, or null when the policy
-- is not refundable. Check-in is the hotel's check-in time in its own zone; subtracting a pure-hours interval from
-- a timestamptz works on the instant timeline, like ZonedDateTime.minusHours. Callers compare it with their "now".
create function free_cancellation_until(policy_id bigint, check_in date, check_in_from time, zone text)
    returns timestamptz language sql stable parallel safe
    return (select ((check_in + check_in_from) at time zone zone)
                   - make_interval(hours => coalesce((select max(r.hours_before_check_in)
                                                      from cancellation_policy_rules r
                                                      where r.policy_id = cp.id and r.penalty_value > 0), 0))
            from cancellation_policies cp where cp.id = policy_id and cp.is_refundable);
```

| ROOM | `air_conditioning` Comfort, `minibar` Comfort, `work_desk` Comfort, `balcony` View & outdoors, `sea_view` View & outdoors, `city_view` View & outdoors, `kitchen` Kitchen, `washing_machine` Kitchen, `bathtub` Bathroom, `private_pool` Wellness |

## Implementation Steps

1. Back up `spring-base/` to the scratchpad (`rollback/spring-base-before-c-srch-02-03.tgz`).
2. Write V6 as above, with a header comment in the V3/V5 style (names follow the schema doc, ids/version/timestamps
   follow this project, scope holds Java enum names).
3. Add the three model classes. Run `./mvnw test -Dtest=SearchControllerTest` to prove `ddl-auto: validate` still passes.
4. `CatalogFixtures`:
   - `HotelBuilder`: `stars(int)`, `type(String code)`, `distance(int metres)`, `currency(String)` (today the insert
     hardcodes `'VND'`, `star_rating` and `distance_to_center_m` are not set).
   - `hotelAmenity(long hotelId, String code)`, `roomAmenity(long roomTypeId, String code)`,
     `bed(long roomTypeId, String code, int quantity)` (look the id up by code in the insert).
   - Keep `roomType()` creating its default plan in `VND`. Currency tests use `bareRoomType` + `ratePlan(...).currency()`.
5. `FreeCancellationSqlTest`: for each case, call `select free_cancellation_until(...)` through `JdbcClient` with a
   policy built by the fixtures. Compare with `FreeCancellation.until(..., now = Instant.EPOCH)`. Cases:
   non-refundable → null; refundable without rules → check-in instant; a 48 h rule with a penalty; a zero-penalty rule
   ignored (largest *penalised* hours wins); `Europe/Berlin` with the 48 h window crossing a DST change (instant
   arithmetic); `Asia/Ho_Chi_Minh` 14:00 check-in.
6. Demo seed (`R__demo_catalog.sql`, still idempotent):
   - Set `distance_to_center_m` on the demo hotels (`update ... from (values ...) where slug = ... and
     distance_to_center_m is distinct from v.metres`).
   - Hotel amenities per demo hotel (resorts: pool, spa, beach_access...; hostel: wifi, bar).
   - Room features and beds per demo room type: Deluxe = king or double + air_conditioning, Family Suite = twin +
     queen + balcony/sea_view.
   - All link inserts use `on conflict do nothing`.
7. `./mvnw test -Dtest='FreeCancellationSqlTest,FreeCancellationTest,SearchControllerPricingTest'`, then start the app
   locally (port 8081 per `.env`) to confirm V6 and the seed apply.

## Risk Assessment

- **DST overlap edge:** for a local check-in time inside the autumn "repeated hour", PostgreSQL and `ZonedDateTime.of`
  may choose different offsets. Check-in times are afternoon and transitions are around 02:00–03:00, so this is
  documented in the function comment, not handled.
- **Time-zone names:** an invalid `hotels.timezone` makes `at time zone` fail the whole query (Java fails the same way
  today). This is already in README "Known limitations".
- **Repeatable seed:** changing `R__demo_catalog.sql` re-runs it on every local DB. Every statement must stay idempotent.
